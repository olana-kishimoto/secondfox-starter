# 画面の契約（DoD）v1 — 業務システムの見本と検査が共有する唯一の正

見本（スターター）はこの契約を体現する。機械検査（ハーネス）はこの契約と
同じ条件を要求する。契約を満たさない見本・生成物は不合格。

## A. 全画面に共通の不変条件

1. 権限で出し分ける
   - view / edit / manage をサーバで判定し、UIの操作も同じ判定で出し分ける
     （サイドバーだけでなくページ内のボタン・リンク・フォームも）。
   - 詳細は「閲覧専用の表示」と「編集」を別物として分ける。edit 権限が
     なければ編集フォームを出さない。
   - 「権限不足」と「データ0件」を別の画面として区別する。

2. 入力を失わせない
   - 保存失敗時は入力値（values）を画面へ返す。空や旧値に戻さない。
   - エラーは項目別（fieldErrors）＋全体（formError）で返し、最初の不正
     項目へフォーカスする。aria-invalid / aria-describedby を付ける。
   - 未保存のまま離脱しようとしたら確認する（離脱ガード）。
   - 共通の ActionState 型（values / fieldErrors / formError）を使う。

3. 競合を検出する
   - 更新は updated_at（または version）で楽観ロックする。
   - 更新・削除・状態変更は「影響行数」を必ず確認し、0件を成功にしない。
   - 競合時は再読込か差分提示を出し、黙って上書きしない。

4. マスタ・明細はリスト
   - 件数が増えてスキャン・比較・編集するデータ（マスタ、明細）は表形式
     （master-table、スマホは data-label）。カードは要約・ダッシュボード・
     少数の強調だけ。
   - 状態は色だけでなく必ず文字（下書き / 受注確定 / 対応が必要）。

5. 失敗・0件・権限・範囲外を混ぜない
   - 取得失敗は ErrorState（再試行導線つき）。「ページが無い」「選択肢が無い」
     と誤表示しない。
   - 0件は「初期0件」と「フィルタ0件」を区別。
   - 範囲外のページ番号は補正して範囲表示が壊れないようにする。

6. 本番にデモデータを入れない
   - 構成seed（ロール・機能・権限）とデモデータ（見本の取引）を別ファイルに
     分け、本番初期化は構成seedだけ適用する。

## B. 画面種別ごとの必須仕様

各画面は必ず next を宣言する：利用者 / 開始点 / 主操作 / 次工程。

- 一覧（ListPage）
  検索・絞り込み・件数・ページング（件数・現在ページ・範囲）。行から詳細へ。
  作成権限があるときだけ「登録」導線。取得失敗・0件を区別。

- 登録・編集フォーム（ActionForm）
  A-2（入力保持）A-3（競合）を満たす。必須・形式の項目別エラー。送信中は
  二重送信を防ぐ。やめる導線に未保存ガード。

- 詳細（Detail）
  閲覧専用表示と編集を分離（A-1）。manage のときだけ削除（確認モーダル、
  window.confirm は使わない）。

- マスタ（Master）
  一覧＋登録・編集・削除（CRUD）を必ず備える。選ぶだけで業務が止まらない
  ように、受注等で参照するマスタは「増やせる」こと。list 形式固定。

- マスタ選択（Picker）
  大きいマスタ前提でサーバ検索＋ページング＋件数。取得上限で「無い」と
  誤判定しない。キーボードだけで単一選択を完了できる（dialog・フォーカス
  トラップ・候補はボタン/選択キー・読み上げ名）。選択済みの表示は検索結果と
  独立。

- ヘッダ明細（受注等）
  明細はリスト（行追加・削除・金額再計算・合計）。明細行はマスタへのFK＋
  表示名スナップショットの両方を持ち、再編集で選択状態を復元する。確定後の
  取消（業務の逆操作）と入力のキャンセルを分ける。
  ヘッダと明細の保存は1トランザクション（RPC）で原子的に行う。途中失敗で明細が
  消える・片側だけ残る状態を作らない。

- 状態遷移
  次にできる操作だけを1操作で出す。遷移はサーバで検証し、権限と現在状態で
  出し分ける。履歴が要る業務は履歴を残す。

- 帳票（印刷）
  帳票は A4 の .sheet（width:210mm・min-height:297mm・box-sizing:border-box）で作る。
  box-sizing:border-box を省くと白紙になる（既知バグ）。
  画面のナビ・サイドバー・印刷ボタンは @media print で隠し、.sheet だけを出力する。
  明細行は break-inside:avoid で改ページにまたがらせない。
  日付は Intl.DateTimeFormat + timeZone:"Asia/Tokyo" で整形する（UTC ずれ防止）。
  金額は右寄せ・¥ 表示（formatYen）とする。
  帳票には「発行日・宛先・合計・内訳」を必ず含める。
  明細は発注時点のスナップショット（受注の name/unit_price）を使い、
  マスタの現在値ではなく記録時点の値を表示する。
  消費税は「確認の引き出し（実装前に客に確認する）」。内税か外税か・端数は
  切り捨て/四捨五入/切り上げか・税率は10%か軽減8%混在か・計算は明細ごとか
  伝票合計か、を確認してから実装する。見本や生成物の帳票で 10% 外税などを
  決め打ちしない。税が要るときは、税区分と端数ルールをデータ側に持たせて
  明細から積み上げる（画面での後付け計算にしない）。

## C. 検査（ハーネス）が要求する対応物

契約を文書で言うだけにせず、機械検査が同じ条件を落とす。

1. 使い捨てDBに全migrationを適用し、最終スキーマで anon / 各業務ロールの
   操作別結果を否定テストする（閲覧ロールが Data API から書けないこと）。
   RLS有効＋policy存在の静的チェックは補助にとどめる。
2. 認証ファイル（src/middleware.ts 等）の削除・空実装を通常生成で禁止。
   未認証・合言葉なし・公開例外を HTTP で検査する。
3. build 失敗を無視しない（acceptance の exit 0 固定をやめる）。
4. レビューの未解決must・レビュー失敗・未実施を fail-closed（dev/本番反映の
   拒否条件）にする。
5. 案件固有の受入条件とは別に、この契約を「共通受入条件」として常設し、
   代表操作を実行した画面証跡（権限・入力エラー・0件・取消）を提出必須にする。
6. 構成seedとデモデータの分離を検査する（本番初期化にデモ取引が入らない）。
